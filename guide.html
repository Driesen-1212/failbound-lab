第 1 章 · 一个大类比讲完整个项目

场景：你在一家有 1000 道菜的餐厅，只能尝 35 口，想找出全场最好吃的菜。
  • 闭眼乱试（随机撒点）：闭上眼睛随便指。35 口里大概能命中 3~4 口特别好吃的（命中率 0.100）。
  • 聪明吃法（贝叶斯优化 BO）：每尝一口都记住味道，推测哪一类菜可能更好吃，下一口专门往那去。听起来必然更聪明，对吧？
  • 菜单标签（描述符）：还没尝的时候能看到的只有菜单信息——照片、辣度、价格。信息的数量就是「维数」。
  • 问题来了：菜单上只有 1~2 条信息时，「聪明吃法」会根据价格瞎猜，自信地绕开真正好吃的菜——真实实验里（预算 400），最差的任务它比闭眼乱试少 33.9 个命中。
  • 我们做的事：先看一眼菜单信息够不够。够，就用聪明吃法；不够，就老实闭眼乱试。这张「先看一眼再决定」的小卡片 = 熔断卡。
  • 最特别的一点：我们不但交卡，还把它自己判错的历史印在菜单上——拒绝过 9 次，4 次拒对，5 次拒错。全场没有第二个人敢把自己的错账打印出来。
一句话：别人在比赛谁的吃法聪明，我们在研究「什么时候聪明吃法会变蠢」——并且给出带价签的判断卡。

第 2 章 · 三分钟版本（项目干了什么）

  1. 背景：找新材料（更好的电池、半导体），候选几千个，实验室一次实验几周、几千块。「下一个实验做哪个」是值钱的问题。全世界默认用贝叶斯优化（BO）。
  2. 没人检验的事：BO 好用的前提是「输入信息（描述符）和目标性质之间有关系」。我们不检验「BO 好不好」，检验「BO 什么时候会坏」。
  3. 怎么做：36 个任务 × 4 种策略 × 30 个种子 × 2 种口径 = 8640 次完整实验轨迹，每条都落盘、可复算。故意把任务变难：目标搞模糊（15 个）、描述符砍到 1~20 维（18 个）。
  4. 三个发现：正常任务 BO 全赢（18/18 显著为正）；信息不足会输（4 个显著为负，最差少 33.9）；机制是「自信地错」（选中点真实分位 0.560 vs 老实撒点 0.613，p=0.031）。
  5. 交付物：一张熔断卡（描述符 ≤2 维就拒绝 BO）+ 完整错误率（真拒 4、误杀 5、显著漏报 0）+ 8640 条可复算数据。比「无脑全用 BO」多命中 26.17 个。
  6. 最重要的诚实：这卡不聪明（p 不显著、会误杀），但它错在哪、错多少钱全写在报告里——错误率定价，而不是假装它万能。

第 3 章 · 概念课（每个词：是什么 → 类比 → 发音）

3.1 材料发现与优化

候选集 candidate poolCAN-di-dit「坎-迪-德」

所有可以试着做的材料清单，几千个。

类比：菜单上那 1000 道菜。

实验预算 budget「巴-吉特」BUD-get

实际能做的实验次数，常用档位 400。

类比：你只付得起 35 口的账单。

目标性质 target property「普罗-泼-提」PROP-er-tee

想优化的那个性质，比如介电常数越高越好。

命中 hit「嘿特」

结束时选中的点落进「全场最好的前 10%」就算命中。随机期望命中率恒为 0.100。

类比：35 口里命中了几道 top 菜。注意：越高越好！

3.2 优化方法

贝叶斯优化 Bayesian Optimization（BO）「贝叶斯 bèi-yè-sī」/ 英文近似 BEY-zhee-un「贝-日恩」，重音在前

边试边学：每测一个点，更新对全貌的猜测，挑下一个最值得测的点。

类比：聪明吃法。口语直接说 B-O（「比-欧」）。

代理模型 surrogate model「瑟-若-给特」SUR-uh-git，重音在第一音节

BO 内部那个「对全貌的猜测」，便宜，代替真实实验做推演。答辩容易被问，先练三遍。

类比：你脑中「这家店大概什么口味」的印象。

高斯过程 Gaussian Process（GP）「高斯 gāo-sī」/ GOW-see-an「高-斯-恩」

最常用的代理模型：一条会给自己留余地的曲线——没测过的地方不但给预测值，还给「我不确定」的范围。

gp_ucb字母连读「G-P-U-C-B」

主策略名 = GP + UCB（Upper Confidence Bound 信心上界）：挑点时预测值 + 不确定性奖励。

类比：「这地方没去过，看起来可能好吃，赌一把」。

基线 baseline「贝斯-莱恩」BASE-line

用来对比的「笨办法」：空间填充（space-filling，均匀铺满，不猜不学）。

坑：报告早期用过 LHS（拉丁超立方抽样）当基线，后来发现铺法退化，换算法后 8640 次全部重跑——这就是答辩自曝第三件事。
种子 seed「西-德」，一个音节

随机数的「起点编号」。同一 seed 跑出的过程完全一样。每个配置 30 个种子 = 排除运气。

类比：同一实验让 30 个人独立做一遍。

3.3 表示与任务

描述符 descriptor「迪-斯克里普-特」dih-SKRIP-ter，重音在 SKRIP

材料的「数字画像」。维数 = 画像由几个数组成：85 维 = 85 个数，2 维 = 只有 2 个。本项目最重要的词，念熟。

类比：菜单标签的数量。

降维 / 消融 ablation「阿-布雷-申」uh-BLAY-shun，重音在 BLAY

故意把描述符砍短（1/2/5/20/85 维），看系统什么时候失灵。

类比：把菜单标签一条条撕掉，看吃货什么时候点错菜。

六个基底名（公开数据集，任务名 = 数据集__变形）
  • matbench_dielectric「代-勒克-垂克」= 介电：预测介电常数。
  • matbench_perovskites「佩-罗夫斯-凯特」= 钙钛矿：一类晶体结构。
  • log_gvrh：剪切模量（多难掰弯）取对数。口语「log 剪切模量」。
  • log_kvrh：体积模量（多难压扁）取对数。口语「log 体积模量」。
  • expt_gap：实验带隙（band gap，半导体导电性的关键量）。口语「实验带隙」。
  • 其他：jdft2d（二维材料）、mp_e_form（形成能）、phonons「佛-农」FOH-nong 声子。
基底 base system「贝斯」

一个材料体系/数据集。36 个任务来自约 5 个基底——独立单元少，是对手最爱打的点，我们主动承认。

3.4 统计课（评委最爱问）

p 值 p-value直接念「p 值」

「如果真相其实什么都没发生，看到这么极端结果的概率」。p<0.05 通常叫显著。

类比：抛硬币连 8 次正面——p 值就是纯靠运气抛出这个结果的概率。

显著性 significant「西格-尼-菲-肯特」sig-NIF-i-cant

p 过了线。报告里 significant=True = 过了检验。

Holm 校正 p_holm「霍姆/厚姆」

一次做 36 个检验总有碰巧显著的，Holm 把「碰巧率」压回去。所有 p 值都报校正后的。

Cliff's δ（delta）「克里夫斯-戴尔塔」

效应量：不看差多少，看两组分开多干净。δ=−0.629 中等偏强。

类比：随便挑一个甲，有 70% 概率比乙高。

秩相关 ρ（Spearman rho）「肉」一个音节；Spearman「斯皮尔-曼」

两个排名像不像。+1 完全同向，0 没关系。衡量「AUC 能不能预报 BO 增益」。

置信区间 CI「因特-沃」IN-ter-vul

真实值大概率落的范围。AUC 0.731 的 CI [0.556, 0.807]——下界接近 0.5（瞎猜），所以说「下界接近随机」。

bootstrap「布特-斯特拉普」BOOT-strap

反复重抽已有数据（2000 次）估波动，不需要数学假设。

类比：全班成绩单反复洗牌抽样，看平均分能波动多大。

留出集 holdout / 留一基底 leave-one-base-out「厚德-奥特」

故意藏几个体系不参与规则拟合，最后拿出来考——检验「换个体系还灵不灵」。

回溯性 retrospective vs 前瞻性 prospectivereh-truh-SPEK-tiv / pruh-SPEK-tiv

retrospective = 事后用已有数据总结；prospective = 先定规则再跑全新实验。我们全部结论是回溯性的——如实写明。

3.5 我们的交付物

熔断卡 fuse cardcircuit「瑟-kit」breaker「布雷-克尔」；口语「熔断卡」

极简规则：描述符 ≤2 维就拒绝用 BO，改用空间填充。

类比：保险丝——电流过大就熔断，宁可断电不让房子烧。它不管哪一秒出事，只管出事时房子别烧。

四个格子（2×2 判定矩阵）
格子含义数量
真拒（拒对）卡说拒绝，实测 BO 确实更差4 个
误杀 false kill「佛尔斯-克尔」卡说拒绝，但 BO 其实更好5 个（区间 21.2%~86.3%）
显著漏报 miss「密斯」卡说放行，实测 BO 显著更差0 个（上界 12.8%；有 1 个 −9.9 但 p=0.89 不显著）
真放卡说放行，BO 更好其余 22 个
代价不对称（为什么误杀 5 个还能接受）

误杀 5 个：最多少赚 31.9 个命中。真拒 4 个：最差躲过 −33.9 的灾难。少赚 vs 踩坑，不对称——所以叫保险丝，不叫仪表。

披露单 disclosure sheet「迪斯-克罗-热」dis-CLOH-zher

我们方法论的名字：判据可复用、阈值如实标注、随卡公布自己的错误率。

第 4 章 · 8640 这个数字怎么来的

8640 = 36 个任务 × 4 种策略 × 30 个种子 × 2 种口径
  • 36 个任务 = 主臂 18（正常任务）+ 消融臂 18（描述符被砍短）。严谨说法：「36 个任务-臂」。
  • 4 种策略 = gp_ucb 等 4 种「下一个实验选哪」的方法。
  • 30 个种子 = 同配置重复 30 次排除运气。
  • 2 种口径 = 两种成本计法（是否启用门控成本）。
必防一句话：评委若说「你有 8640 个数据点呢」——标准回法：「有效独立单元只有 36 个任务、约 5 个基底，8640 是轨迹数不是独立样本数，报告里按体系整簇重抽处理了。」

第 5 章 · 三个核心发现（复述版）

发现一：BO 不是万能的。正常任务 18/18 全赢；信息不足的任务 4 个显著输，最差少 33.9 个命中。同一套方法，换个任务就翻车。

发现二：什么时候翻车，跟「做什么材料」关系不大，跟「怎么描述材料」关系很大。同一体系，描述符砍到 2 维就翻车，85 维就稳赢。失效在表示里，不在体系里。（严格说：翻转只发生在部分体系——expt_gap 就不翻转，这句限定必须带上。）

发现三：失效的机制是「自信地错」。失效时 BO 把预算投到更低的真实分位（0.560 vs 0.613，五个体系方向全一致，p=0.031）。它不是运气差，它是认真地、系统地绕开好答案。

第 7 章 · 评委问什么，你怎么答

Q：你这卡不就是一条 if 语句吗？
A：对，而且是设计选择。复杂规则我们搜过——留出检验转负（−19.2），所以不交付。这条简单规则的每一类错误都被 8640 次实测定过价。
Q：36 个任务都来自 matbench，独立吗？
A：不独立，独立基底只有约 5 个，我们按体系整簇重抽处理统计推断，并把「留一基底错误率 0.28–0.44」写在报告里。这是最大局限，我们选择说出来而不是藏。
Q：ρ=0.820 不是说相关性很强吗？
A：那个 0.820 测的是同一体系内换表示；一跨体系，8 个基底级点实测 ρ=0.167，p=0.69——不是估不出来，是测不出关系。所以 AUC 只能当诊断量，不能当开关。
Q：你说漏报 0，真的一个负的都没有？
A：显著漏报 0。放行区里有一个任务 BO 差 9.9，但 p=0.89 不显著——这个数在 tests.csv 里，欢迎查。
Q：为什么不跑新实验证明前瞻性？
A：判据已公开，任何「知道答案后的新跑」都没有证明力。我们交付的是错误率定价和可复算数据，前瞻验证写在后续计划里。

第 8 章 · 忘词急救包（现场卡壳就说这些）

  • 被问懵：「这个问题我们的报告 §4.4 有完整分析，我复述核心结论是……」（争取 3 秒思考）
  • 数字忘了：「具体数字在报告里有，方向我可以确定地说：……」
  • 被打断：停下，听完，说「您指的是……对吗」再答。
  • 万能金句（背下来）：「科学里最贵的不是算力，是知道什么时候不该算。」

第 9 章 · 怎么操作（手把手，照抄就能跑）

这一章教你亲手把项目跑起来。每条命令都解释了它在干什么，照抄即可。

9.1 跑演示程序 ask.py（现在就能跑）

它读我们已存盘的实验结果（tests.csv 等，共约 300KB），2 秒输出一张卡的裁决。不用联网。

1
打开终端
按键盘 Win + R，输入 cmd 回车。弹出的黑窗口就是终端——它是「用打字代替点击来操作电脑」的工具。
2
进入项目目录 
cd /d D:\failbound-lab
「cd」= change directory（换文件夹），告诉终端「接下来在这个文件夹里干活」。/d 表示允许跨盘符跳转。
3
告诉程序数据在哪 
set FAILBOUND_RESULTS=agent_lab\results
「set」= 设一个环境变量（临时记号）。ask.py 会读这个记号去找结果文件夹。（等交付闭环做完、脚本进公开仓库后，这一步会省掉。）
4
跑起来（三个例子） 
python ask.py --task matbench_dielectric__pca1   :: 拒对的例子
python ask.py --task matbench_dielectric__rp5    :: 放行但略亏的例子
python ask.py --task matbench_log_gvrh__pca2     :: 拒错的例子（误杀）
「python ask.py」= 运行这个脚本；「--task xxx」= 指定要看哪个任务。屏幕会输出：描述符几维 → 卡的判断 → 实测数字 → 三级裁决（拒对 / 拒错 / 放行对 / 放行亏）。
看懂输出：拒绝优化 = 卡不让用 BO；USE_BO = 卡放行；最后一行「裁决」是拿实测数据给卡打分——它会自己承认「拒错了：误杀」，这就是答辩最敢的一招。

9.2 复算主数字 verify.py（交付闭环做完后可用）

python verify.py

30 秒内打印两个数：+26.17（熔断卡比全用 BO 多命中）和 −9.23（旧两条件卡），并列出由哪 36 行、哪些种子配对算出——与报告逐位一致。这是给评委「自己动手验一条」用的。

9.3 打开交互控制台（网页，拖滑块）

1
双击打开 failbound-console.html（在仓库目录里），或访问 GitHub Pages 主页。
2
拖两个滑块：θ（AUC 阈值）和 d（维度阈值），右侧实时显示「放行 / 拒绝」。
⚠️ 注意：控制台当前默认 θ=0.600 / d=3 是旧版卡，正在统一改成主卡 dim≤2（总账 #2 的一项）。改完之前别拿它演示。

9.4 自己查数字（Excel 就能干）

tests.csv（主结果表）

用 Excel 打开 unzipped\agent_lab\results\tests.csv。重点列：budget（预算档）看 400；strategy 看 gp_ucb；use_gate 看 False；mean_bo / mean_base = BO 与基线的平均命中；p_holm = 校正后 p 值。

task_props.csv（任务属性表）

看每个任务的 dim（描述符维度）和 separability_auc。两表用 task 列对照——「维度 ≤2 的行，BO 是不是普遍输给基线」一眼可见。

9.5 答辩当天的操作（提前做，不做就翻车）

1
前一晚：把演示目录整个拷进 U 盘 + 现场电脑双备份；预录 40 秒成功录屏当退路。
2
上台前：终端窗口和 ask.py 输出提前开好、字号调大（至少 20pt）；断网状态试跑一次确认可用。
3
第 3 页时：Alt+Tab 切到终端，跑「一拒对 + 一拒错」两条命令（30 秒内），指着「拒错了：误杀」那行说：「这是我们自己卡的错账。」
4
纪律：现场不开 IDE、不现场打字输长命令、不依赖任何网页。跑挂了就切录屏，说「这是刚才那条命令的输出」。
